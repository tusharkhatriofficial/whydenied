Overview

Turn AWS AccessDenied errors into reviewed pull requests.

WhyDenied watches CloudTrail, works out the one permission a role is missing, and opens a pull request against your Terraform that grants exactly that. A human reviews and merges; nothing touches IAM directly.

Safety model

Built to be merged with confidence

A tool that writes IAM policy has to be conservative. These are the rules WhyDenied follows.

  1. S1

    The fix is generated by code, not by AI

    The model only writes review notes, so an incorrect or manipulated response cannot widen permissions.

  2. S2

    Exact scope

    Each fix grants one action on one resource. Wildcard actions are refused.

  3. S3

    Only missing Allow statements

    Explicit denies, SCPs, permissions boundaries and session policies are reported for a human to handle.

  4. S4

    Human approval

    Changes arrive as pull requests. Nothing is applied without a merge.

  5. S5

    Untrusted input

    Event data reaches the model as delimited data, and its output is validated and stripped of markup before it reaches a pull request.

  6. S6

    Least privilege for WhyDenied itself

    The analyzer reads only SSM parameters under /whydenied/ and writes only to its own table.
