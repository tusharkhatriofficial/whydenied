Self-hosted in your AWS account

Turn AWS AccessDenied errors into reviewed pull requests.

WhyDenied watches CloudTrail, works out the one permission a role is missing, and opens a pull request against your Terraform that grants exactly that. A human reviews and merges; nothing touches IAM directly.

Setup

Try it, check your repo, deploy

Steps 1 and 2 run from this page with nothing installed. Step 3 deploys WhyDenied into your own AWS account.

  1. 1

    Try it

    Paste an AccessDenied error from a log, a terminal or a CI run. WhyDenied parses it and writes the Terraform it would propose.

    0 / 4000

    The message can include surrounding text. Nothing is stored.

  2. 2

    Check your Terraform

    WhyDenied matches a denial to the aws_iam_role with the same explicit name. Check which roles in a public repository it can fix today.

    github.com/

    Accepts owner/name or a full GitHub URL. Files are read in your browser from the default branch, up to 200 .tf files.

  3. 3

    Deploy to your AWS account

    Choose your options, launch the stack, then store the secrets it reads. You need a CloudTrail trail recording management events in us-east-1.

    Fix pull requests are opened here. It can be private.

    AI review notes

    The model writes review notes only. The fix is always generated by code.

    Alerts

    a Launch the stack

    Opens the CloudFormation console in us-east-1 with your options filled in. Review and create.

    Launch in AWS
    Prefer the SAM CLI?

    b Store your secrets

    Run these with your own values. Tokens stay in your account: they go from your terminal to SSM Parameter Store and never pass through this page.

    The GitHub token is a fine-grained personal access token scoped to your Terraform repository, with Contents and Pull requests set to read and write.

    c Verify

    Trigger a denial from a role defined in your repository. Within about 30 seconds a pull request titled WhyDenied: allow <action> for <role> appears.

Safety model

Built to be merged with confidence

A tool that writes IAM policy has to be conservative. These are the rules WhyDenied follows.

  • The fix is generated by code, not by AI

    The model only writes review notes, so an incorrect or manipulated response cannot widen permissions.

  • Exact scope

    Each fix grants one action on one resource. Wildcard actions are refused.

  • Only missing Allow statements

    Explicit denies, SCPs, permissions boundaries and session policies are reported for a human to handle.

  • Human approval

    Changes arrive as pull requests. Nothing is applied without a merge.

  • Untrusted input

    Event data reaches the model as delimited data, and its output is validated and stripped of markup before it reaches a pull request.

  • Least privilege for WhyDenied itself

    The analyzer reads only SSM parameters under /whydenied/ and writes only to its own table.
